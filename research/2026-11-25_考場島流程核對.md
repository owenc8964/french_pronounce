## 二、寫入的 clb7_* 會不會在同步時弄丟

sync_supabase.js 的規則（69–108）：陣列＝各裝置聯集（用 ts 去重）；物件＝逐筆比 `last`，新的贏；上傳（126–132）是把本機所有 clb7_* **整包**送上去。

| key | 寫在哪 | 形狀 | 結果 | 說明／改法 |
|---|---|---|---|---|
| `clb7_exam_known`（跳過） | 36、100、165 | `{題號:{n, last}}` | ✓ | 照慣例。小缺點：兩台裝置都跳過同一題時，取 last 較新的那份，`n` 不會相加（例：A 跳 3 次、B 跳 1 次且較晚 → 合併後 n=1）—— 推論。影響只是出現頻率，不會丟題 |
| `clb7_exam_done`（講過） | 36、127、191 | 同上 | ✓ | 同上 |
| `clb7_exam_mine`（我會這樣講） | 53 | 陣列，每筆有 `ts` | ✓ | 聯集去重，不會被整包覆蓋弄丟。本機只留最後 300 筆，但雲端舊筆會在下次拉回來時被加回，所以實際上限比 300 寬一點，無害 |
| `clb7_toolbox_use`（句型有沒有用到） | toolbox.js 134 | `{句型:{pick, used, last}}` | ✓ | 照慣例 |
| ⚠️ `clb7_exam_dims`（每題選的維度） | 98–99 | `{題號:[維度…]}`，**值是陣列、沒有 last** | ✗（小） | 合併時兩邊都沒有 last → 0 比 0 → **一律雲端那份贏**（sync_supabase.js 101）。後果：① 在 A 裝置改了維度、還沒上傳前就拉了雲端（例如另一台剛好較晚上傳）→ 改的被蓋回去；② 把某題的維度全部取消時程式是**刪掉那個題號**（99），合併規則看到本機沒有就把雲端的加回來（sync_supabase.js 100）→ 取消的維度會「復活」—— 推論，未實跑。**改法**：存成 `{題號:{d:[…], last:時間}}`，取消時存空陣列 `{d:[], last}` 不要 delete；讀取處（79）改讀 `.d` |
| 金幣、告示牌看過、島主見過 | 129、193、207、222 寫進 `S` | town.html 329 `town_sample_v2` | 不同步（原設計） | town.html 19 行註明小鎮存檔只存本機、不接同步。不會被覆蓋，但換裝置時告示牌會再自動打開一次、金幣各算各的 —— 非考場島特有 |

## 總結
- 跳過該有的都有：整題跳過、不計分、不進錯題、灰色無提示、記錄不刪題、全跳過也不卡空。唯一缺口是**開始講之後沒有「不講了」**，只能假裝講完。
- 同步大致照慣例；**每題選的維度**那個 key 不是「物件＋last」，取消的維度可能被雲端加回來。
- 沒登入、網路壞、語音壞都不會卡死；第二題選到空類別會出錯（內容是否真有空類別未查證）。
