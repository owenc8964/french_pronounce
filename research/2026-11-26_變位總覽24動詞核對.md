## 二、✗1 變化表 ⚠️ 標記標錯格（`verb_forms.html` 的 `cellMark()`，第 956–968 行）

`cellMark()` 判斷現在式的方法是「這一格是不是用 nous 的詞幹開頭」。這次多了拼字例外的動詞，這個判斷會把格子標錯（實跑 `tools/tmp_q83_mark_check.js`）：

| 動詞 | 現在標在哪裡 | 應該標在哪裡 |
|---|---|---|
| manger | 只有 `ils mangent` 標「ils 詞幹變了」← **標錯** | `nous mangeons`（多了 e） |
| déplacer | je／tu／il／vous／ils 都標「詞幹變了」← **正好相反** | `nous déplaçons`（ç） |
| appeler | 只有 `ils appellent` | j'appelle／tu appelles／il appelle／ils appellent（ll） |
| rappeler | 同 appeler | 同 appeler |

另外有兩個小問題：imparfait 那一欄，manger／déplacer 的 `nous mangions`／`nous déplacions` 沒有標記（這兩格才是最容易打錯的）；offrir／accueillir 的 -ir 動詞用 -e 字尾，現在也沒有標記。

**改法（提案，未動檔）**：在 `cellMark()` 前面加一段針對拼字例外的判斷，有 `impf` 的動詞和 -eler 動詞直接指定要標的格：
```js
// 加在 switch 前面
if (v.impf && t.id === 'present')   return i === 3 ? (v.pres[3].includes('ç') ? 'c → ç' : '多一個 e') : '';
if (v.impf && t.id === 'imparfait') return (i === 3 || i === 4) ? (v.pres[3].includes('ç') ? 'ç 拿掉' : 'e 拿掉') : '';
if (t.id === 'present' && /eler$/.test(v.inf) && [0,1,2,5].includes(i)) return 'l → ll';
```
offrir／accueillir 想標的話：`if (t.id==='present' && /ir$/.test(v.inf) && /^(e|es)$/.test(f.slice(stemNous(v).length)) && i<3) return '-er 型字尾'`（可做可不做）。

## 三、✗2 鐵砧打字會冤枉 `je paye`

鐵砧和 verb_sprint 打字時，答案只接受 `drillForms()` 給的那一種寫法。比對時重音會先去掉（所以 complèterai 跟 compléterai 都算對，ç 打成 c 也算對，只是會提醒「注意重音」），但 **`paye`／`payes`／`payent`／`payerai`／`payerais`／`que je paye` 是字母不同**，會被判錯。這兩種寫法 Wiktionnaire 都列為正確（見上方網址）。

**改法（提案）**：在 `verbs_full.js` 的 `drillForms()` 最後加一個「也算對」的對照表，只影響打字比對，不影響總覽顯示：
```js
const ALT = { payer: { present:['paie|paye','paies|payes','paie|paye',null,null,'paient|payent'],
                       'futur-simple':'paier>payer', conditionnel:'paier>payer', subjonctif:['paie|paye','paies|payes','paie|paye',null,null,'paient|payent'] } };
```
（字串 `'paier>payer'` 的意思是把 futur 詞幹換掉，再多產一組答案。格式可以再簡化，重點是用 `|` 多給一個正確答案。）

ℹ️ 順帶一提：因為比對會把 ç 和重音一起去掉，鐵砧實際上**不會因為 déplacons（少 ç）判錯**，只會提醒「注意重音」。這是原本就有的設計（重音錯算對但提醒），列出來只是讓 Owen 知道：ç 這個例外在打字練習裡只會被提醒，不會被當成錯。

## 四、降權會不會讓新動詞永遠不出

**`town.html` 的鐵砧（`forgeCells` × `conjCorpus`）✓ 不會。**
- 24 個新動詞**都不在** `verb_freq.js` 裡，所以全部拿到 0.5。舊的 25 個動詞全都在語料表裡，所以這次的改動**只影響新動詞**，沒有誤傷舊的。
- 模擬結果：假設每一格都還沒練過，看新動詞佔一爐的比例（`tools/tmp_q83_weight_check.js`）：

| 時態 | 改之前（1） | 改之後（.5） | 新動詞最冷門的一格被抽到的機率 |
|---|---|---|---|
| présent | 29% | **17%** | 0.12% |
| passé composé | 43% | 27% | 0.19% |
| imparfait | 49% | 33% | 0.23% |
| futur simple | 51% | 34% | 0.24% |
| conditionnel | 50% | 34% | 0.23% |
| subjonctif | 55% | 38% | 0.26% |
| plus-que-parfait | 62% | **45%** | 0.31% |

- 白話：新動詞不但不會消失，**在過去式和未來式的爐裡還佔了三到四成**。原因是舊動詞在這些時態的語料次數本來就少，很多也只拿 0.5，所以降權在這些時態幾乎沒有差別。如果 Owen 的本意是「先練核心」，這些時態的稀釋還是很明顯。而且舊格練到反射以後，權重會降到 0.4，新格還沒練過是 3，實際比例會比上表更高。
- **提案（看 Owen 要不要）**：不在語料表的動詞改成 `.3`，或是再乘上等級係數（`lvl==='B1' ? .5 : 1`）。這不急，因為不會有動詞永遠不出。

**真的「永遠不出」的地方（都是這次之前就有的設計，列出來給 Owen 判斷）**
- ⚡ 變位（礦坑的 `conjPick`）只從 `CONJ_VERBS` 的核心 11 個動詞抽 → 24 個新動詞都不會出。這是原本的設計。
- quest 填表（`tenseTable`）只抽 A1／A2 → **agrandir、déplacer、ennuyer、accueillir、valoir、paraître、éteindre、réduire 這 8 個 B1 動詞永遠不會出現在填表**；其他 16 個會出。
- ⚠️ 前後不一致：quest 的 `tbVerbW()` 和 verb_sprint 的 `corpusMul()`，遇到語料表沒有的動詞**還是回傳 1**，只有 town 改成了 .5。所以在 quest 填表裡，新動詞的權重（1）反而比語料裡 0 次的舊動詞（.5）高。**提案**：三個地方統一（都改 .5，或都維持 1），等 Owen 決定。
