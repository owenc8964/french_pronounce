# 語音辨識可行性（Web Speech API，fr-FR）

> 排程 `clb7-game-dawn` 2026-09-13 產出。對應 `GAME_ROADMAP.md` 佇列項 **R1**，
> 要回答的問題：**「吶喊招式」（對麥克風唸法文句子、比對辨識結果）在 Owen 的手機上跑不跑得動？**
> 方法：官方文件（MDN／Chrome for Developers／WebKit 論壇）＋開發者實測回報，非一手實測（排程不開瀏覽器）。

---

## 一句話結論

**能做，但只能是「加分招式」不能是核心機制**——瀏覽器支援拼圖破碎（iOS 上非 Safari 的瀏覽器完全不支援）、
法文在 iOS 離線辨識目前不可靠（官方本地語音包對非英文語系的語尾判斷會拖慢數秒）、
辨識結果的容錯必須做寬鬆比對（不能要求逐字相符）。**建議：feature-detect 不支援就不出現按鈕（⛔ 不報錯，
這點 B4 驗收標準已經寫對了），支援時當作「額外攻擊手段」而不是唯一破關路徑。**

---

## 一、瀏覽器支援矩陣

| 平台／瀏覽器 | 支援狀況 | 備註 |
|---|---|---|
| **桌機 Chrome / Edge** | ✅ 支援（`webkitSpeechRecognition`），Chrome 25+ | 雲端辨識，需要網路 |
| **桌機 Safari (macOS)** | ✅ 支援，Safari 14.1+ | |
| **桌機 Firefox** | ⛔ 預設關閉 | 藏在 `about:config` 的 `dom.webspeech.recognition.enable`，一般使用者不會打開 |
| **iOS Safari** | ✅ 支援，iOS/iPadOS 14.5+（`webkitSpeechRecognition`） | ⚠️ 有已知 bug（見下） |
| **iOS 上的 Chrome / 其他瀏覽器** | ⛔ **完全不支援** | Apple 規定 iOS 上所有瀏覽器都要用 WebKit 引擎，但這些外殼瀏覽器沒有掛上 Safari 的語音辨識實作——**這不是「換瀏覽器就能解決」的問題** |
| **Android Chrome** | ✅ 支援，Chrome 25+ | 雲端辨識（Google 語音服務），需要網路 |

**對這個專案的意義**：如果 Owen 平常用的是 iPhone 上的 Chrome（很多人手機瀏覽器預設是 Chrome），
**語音招式會完全不出現**——必須做 feature detection（`window.SpeechRecognition || window.webkitSpeechRecognition` 存不存在），
剛好符合 B4 驗收標準已經寫的「不支援時按鈕不出現、⛔ 不報錯」。

## 二、需不需要網路

**預設都需要**——Chrome／Android Chrome／桌機 Safari 都是把錄音送到雲端（Chrome 送 Google、Safari 送 Apple）辨識，
**離線完全不能用**。

2026 年才有的例外：
- **Chrome 139** 開始有「on-device（離線）Web Speech API」的實驗性支援，但目前 **Android 版 Chrome 還沒跟上**
  （官方 Chromium 討論串明講 Android 上還不支援 on-device）。
- **Safari** 可以在使用者授權＋下載「語音包」後離線辨識，**但目前只有英文測起來可靠**；
  非英文語系（含法文）在離線模式下「判斷一句話講完了沒」會多花好幾秒，等於離線法文辨識體驗很差，
  **實務上等於還是要靠雲端**。

**對這個專案的意義**：吶喊招式預設要有網路才能用。這對 Owen 的使用情境（在家/通勤，多半有 wifi 或行動網路）
影響不大，但如果他人在地鐵/無訊號環境練習，這招會直接失效——**要處理「辨識逾時/失敗」的情況，
比照跳過鐵律，失敗就當作沒出這招，不要卡住戰鬥**。

來源：
- [SpeechRecognition - MDN](https://developer.mozilla.org/en-US/docs/Web/API/SpeechRecognition)（"Your audio is sent to a web service for recognition processing, so it won't work offline"）
- [on-device speech recognition explainer - WebAudio/web-speech-api](https://github.com/WebAudio/web-speech-api/blob/main/explainers/on-device-speech-recognition.md)
- [A Deep Dive into the Web Speech API](https://blog.addpipe.com/a-deep-dive-into-the-web-speech-api/)

## 三、隱私

- Chrome：錄音送到 **Google** 的雲端語音服務處理
- Safari：錄音送到 **Apple** 的雲端語音服務處理（除非離線語音包生效）
- 這是瀏覽器原生行為，不是這個專案額外接的第三方服務——**不需要另外找 API/存金鑰**，
  但等於「Owen 唸的法文句子」會離開裝置。純自用、內容是練習句不是隱私資料，風險低，
  但如果之後要跟 Owen 講清楚這個招式在做什麼，這點值得提一句（「用瀏覽器內建的語音辨識，跟 Siri/Google 小幫手同一套機制」）。

## 四、準確率

沒有找到「Web Speech API 辨識法文」的獨立跑分數據（廠商不公開）。旁證：
- 通用法文 ASR 系統（非瀏覽器內建，學術評測）的 WER（詞錯率）大約落在 **20%–25.6%** 之間，
  代表就算是專門的法文語音辨識系統也不是零錯誤。
- iOS Safari 已知有結果不穩定的回報：`onresult` 有時不觸發、`interimResults` 行為不一致、
  麥克風有時不會自動停止聆聽。

**對這個專案的意義**：⛔ **不能拿「辨識結果跟句子逐字相符」當判定招式成功的標準**——20% 上下的錯字率
代表講對了也可能被判失敗，這會變成新的挫折來源（違反鐵律 4「先是遊戲」與 memory `feedback_fun_is_the_engine`）。
**應該做寬鬆比對**（例如：關鍵字命中幾成、或忽略重音/大小寫的模糊字串比對），
且**辨識失敗預設判定為「有出招但威力打折」而不是「出招失敗」**——後果永遠落在遊戲角色的傷害數字上，
不是判定 Owen「講錯了」。

來源：
- [SpeechRecognition having issues in Safari - Apple Developer Forums](https://discussions.apple.com/thread/255492924)
- [Unclear interimResults implementation in Safari iOS - WebKit](https://developer.apple.com/forums/thread/775699)

## 五、給 B4（吶喊招式原型）的具體建議

1. **Feature detect 優先**：`const SR = window.SpeechRecognition || window.webkitSpeechRecognition; if (!SR) return;`——
   偵測不到就不渲染這個招式按鈕，其他招式（攻擊/法術/藥水）正常可用，⛔ 不彈錯誤訊息。
2. **lang 設定 `'fr-FR'`**，`interimResults:false`、`maxAlternatives:3`（多拿幾個候選結果，用最接近的比對，
   緩解 WER 造成的誤判）。
3. **比對用寬鬆字串相似度**（例如正規化去重音+去大小寫後算編輯距離門檻，或關鍵詞命中率），
   ⛔ 不要求逐字相符。
4. **逾時與失敗處理**：`onerror`／`onnomatch`／超過 N 秒沒結果，一律當作「這次沒聽清楚」，
   讓玩家可以重試或直接改用別的招式（跳過鐵律的延伸）。
5. **句子來源**：比照鐵律 1，唸出來比對的句子只能來自 `sentences.js`，⛔ 不自創。
